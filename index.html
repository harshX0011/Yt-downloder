Why this page cannot download anything

You are looking at a static page on GitHub Pages. The app itself is a Python service that does the extraction and the file transfer, and Pages cannot run one. Deploy it with the button above and you get a working instance at your own URL in about five minutes.

And why no YouTube downloads, anywhere

There is no official or legal mechanism to turn a YouTube URL into an MP4 file, so this project does not provide one:

  • The YouTube Data API v3 returns metadata only. No Google API returns a media stream or a file.
  • YouTube's Terms of Service prohibit downloading except through a feature YouTube itself provides.
  • The only sanctioned downloads are Premium offline, inside the YouTube app, and YouTube Studio or Google Takeout for a channel you own. Neither is exposed programmatically.
  • Tools that fetch the streams anyway defeat YouTube's signature descrambling, rate limiting and bot detection. Those are technical protection measures, and this project does not work around them.

So a YouTube link here gets real metadata from an official Google endpoint, the official embedded player, and a plain refusal that lists the authorized alternatives. POST /api/download on a YouTube URL returns 422, and a test keeps it that way.

Get a live instance

  1. Click Deploy your own, free above and sign in to Render with GitHub.
  2. Render asks for YOUTUBE_API_KEY. Paste one from the Google Cloud Console with YouTube Data API v3 enabled, or leave it blank: the app still runs on YouTube's public oEmbed endpoint, just without durations.
  3. Apply. The first Docker build takes four to six minutes, then /api/health answers {"status":"ok"} at your URL.

Free instances sleep after 15 minutes idle and take about a minute to wake. To run it on your own machine instead: 

git clone https://github.com/harshX0011/Yt-downloder.git
cd Yt-downloder
docker compose up --build
# then open http://localhost:8000

How it is built

A FastAPI backend with a job queue, server-sent progress and ffmpeg remuxing to MP4, behind a responsive single-page frontend with no build step. Every outbound URL and every redirect hop is checked against private, loopback, link-local and IPv4-mapped-IPv6 ranges before it is fetched, the byte ceiling is enforced while the transfer runs rather than trusted from Content-Length, and yt-dlp is driven with geo-bypass off, no cookies and its own extractor allowlist pinned to the list above.

107 tests, linted, and CI builds the container image and smoke-tests it running on every push.
